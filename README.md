## Git Commands Used

I used Git to manage my practice files, maintain separate branches, record changes, and push my work to GitHub.

### 1. Repository Setup

- `git init` – Initialized a Git repository in the project folder.
- `git branch -M main` – Set the main branch name to `main`.
- `git status` – Checked the current branch and the status of files.

### 2. Tracking and Saving Changes

- `git add <file-or-folder>` – Staged files before committing them.
- `git add .` – Staged all eligible changes in the project.
- `git commit -m "message"` – Saved staged changes with a descriptive commit message.
- `git log --oneline` – Viewed the commit history.

### 3. Working with Branches

- `git branch` – Listed local branches.
- `git switch -c <branch-name>` – Created a new branch and switched to it.
- `git switch <branch-name>` – Switched between existing branches.
- `git merge <branch-name>` – Merged changes from another branch into the current branch.

I used separate branches for Python practice, DSA practice, and assessment work before combining the completed work into the main branch.

### 4. Connecting and Uploading to GitHub

- `git remote add origin <repository-url>` – Connected the local repository to GitHub.
- `git remote -v` – Checked the configured remote repository.
- `git push -u origin <branch-name>` – Uploaded a branch to GitHub and set its upstream.
- `git push origin main` – Pushed the updated main branch to GitHub.

### 5. Checking the Final Repository

- `git branch -a` – Listed local branches and remote-tracking branches.
- `git status` – Checked for uncommitted changes.
- `git log --oneline --graph --all` – Viewed the commit history and branch relationships.

## Git Workflow

The workflow followed was to initialize the repository, organize the files into folders, create separate branches, stage and commit the changes, push the branches to GitHub, and merge the completed work into `main`.

This helped me practise version control and maintain an organized record of my learning and assessment work.
